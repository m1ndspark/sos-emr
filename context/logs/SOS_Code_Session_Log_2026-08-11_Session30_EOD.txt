--- ZOHO FORM LOOKUP MESSAGE - RESOLVED ---

Root cause of the message never showing: the Lookup Message field was
set HIDDEN. A hidden field never renders, so the prefill write succeeded
and nobody saw it. This closes the Session 29 open issue.

Final design:
- Message field is VISIBLE, placed inside grid "Email Typo Alert".
- The GRID is hidden by default and shown by a form rule:
  If Lookup Status Is not empty -> Show grid. (Started as Is NOT_FOUND;
  changed because a FOUND result reverted the rule and the success
  message vanished after flashing.)
- get_partner_referral_contact rewritten: the searched email address is
  now embedded in BOTH messages ("We couldn't find x@y.com..." /
  "We found the details for x@y.com...") so a stale message is
  self-identifying.
- A temporary DIAG suffix (received email + server time appended to
  Lookup_Message) proved the webhook fires on every Search click. It
  has been removed from the live function.

Zoho Forms quirks accepted, not fixed:
- Clearing the email with the X does not release the stored field value
  or re-trigger any rule; the value updates only on the next Search
  click or a page refresh. The embedded email in the message makes this
  harmless.
- Testing repeat submissions needs a fresh incognito window per try -
  Zoho persists partial entry in the session.
